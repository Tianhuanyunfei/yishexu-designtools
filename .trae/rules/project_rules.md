3. 按照版本号从新到旧排序
4. 每个版本显示独立的标题栏，包含版本号和发布日期
5. 每个更新项使用•符号标记，清晰展示每个版本的更新内容
代码定位规则（避免浪费 token）：
1. 严禁自行编造英文名/变量名去搜索（例如把「轴后端伸出长」猜成 rod_to_rear_cover），这类猜测几乎搜不到。
2. 用户指定的中文名称，先用中文原文直接搜索，代码中的中文标签、注释、字段说明通常能直接命中。
3. 从命中位置顺藤摸瓜找到对应的变量名/key/坐标，再做后续修改。
4. 严禁在未命中时就通读整个文件或大范围搜索；找不到时应先向用户确认准确名称，而不是自己猜。
验证规则（严禁自作主张跑验证）：
1. 改完代码直接交付，不要自动跑脚本、命令去验证，用户自己验证速度更快。
2. 严禁反复跑同一条验证命令、或换着参数重复验证同一处改动；这类重复执行会长时间占用对话，让用户以为卡死。
3. 只有在用户明确要求「验证一下」「跑一下看看」时才执行验证，且只跑一次。
4. 若确实需要说明改动效果，用已有代码/数据推理说明即可，不要启动进程。
